<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser session -> API conversation record | The browser can request session creation and polling, but the server owns the authoritative session state. |
| Browser -> same-origin rewrites | Conversation routes are reached through Next.js rewrites, which must not leak raw backend URLs or storage paths. |
| Session record -> inline turn cards | The UI renders turn/session state, but it must not become the source of truth for live conversation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01-01 | Tampering | `services/api/app/services/conversation_jobs.py` | medium | mitigate | Keep the conversation session record server-owned in SQLite and validate session ids at the API boundary. |
| T-04-01-02 | Information disclosure | `apps/web/next.config.ts` | medium | mitigate | Serve conversation traffic only through same-origin rewrites and never expose raw backend or storage paths in the browser. |
| T-04-01-03 | Repudiation | `apps/web/components/studio-shell.tsx` | low | accept | Session-local UI state may reset on refresh by design, but the authoritative session record remains server-side. |
</threat_model>
