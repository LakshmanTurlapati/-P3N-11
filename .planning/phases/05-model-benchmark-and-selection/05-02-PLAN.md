<objective>
Add the VAD and TTS benchmark adapters that produce comparable evidence for model selection.

Purpose: Compare the current Silero and CosyVoice baselines against one alternate VAD and one alternate TTS/voice-cloning candidate while preserving provider interfaces, license gates, and deterministic local tests.
Output: benchmark adapter package, fixture-only runner behavior, blocking human verification checkpoints for suspicious packages, and VAD/TTS benchmark tests.
Scope note: This plan may record setup/runtime/license blockers instead of running real GPU-heavy candidates in the local workspace. It must not rank a candidate from research notes alone.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Human checkpoint -> runtime install path | Suspicious or unfamiliar packages must not be installed or trusted before approval. |
| Provider adapter -> model runtime | Candidate code may fail setup or require GPU dependencies unavailable locally. |
| Candidate result row -> recommendation | Runnable evidence and blocker evidence must stay distinct so reports do not rank unsupported models. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-02-01 | Tampering / Supply chain | alternate VAD install path | high | mitigate | Blocking human checkpoint before any FireRedVAD, TEN VAD, or other alternate VAD install/runtime use. |
| T-05-02-02 | Tampering / Supply chain | alternate TTS install path | high | mitigate | Blocking human checkpoint before any Qwen3-TTS, OpenVoice, F5-TTS, or other alternate TTS install/runtime use. |
| T-05-02-03 | Spoofing | benchmark results | medium | mitigate | Emit `status=blocked` rows for unapproved or failed candidates and prevent blocked candidates from being recommended. |
| T-05-02-04 | Denial of service | model adapter execution | medium | mitigate | Keep local tests fixture-only and require external/GPU evidence to be captured as report rows rather than running heavy models during normal pytest. |
</threat_model>
