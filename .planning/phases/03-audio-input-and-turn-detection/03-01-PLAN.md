<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> audio-turn API | Mic capture and upload blobs are untrusted until the control plane validates them and stores them as queued jobs. |
| Browser -> spoken-turn list | The UI can only reflect the current session state; it must not become the source of truth for audio-job status. |
| API -> object store | Captured audio must remain server-side and be served only through controlled same-origin routes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering / DoS | `services/api/app/routes/audio_turns.py` | high | mitigate | Validate MIME type and size before queueing, store the blob as a job artifact, and keep the request path short-lived. |
| T-03-02 | Information disclosure | `services/api/app/services/audio_turn_jobs.py` | medium | mitigate | Keep object-store paths server-side and expose only controlled same-origin job/status/audio routes. |
| T-03-03 | Tampering | `apps/web/components/studio-shell.tsx` | medium | mitigate | Keep spoken-turn state separate from generation attempts and create jobs only through the backend route, not through client mutation. |
| T-03-SC | Tampering | capture payloads | low | accept | Session-scoped spoken-turn state is expected in this phase and is not persisted across page refresh. |
</threat_model>
