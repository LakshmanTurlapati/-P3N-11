<objective>
Add structured logging, then document and audit the internal beta handoff for rented GPU infrastructure.

Purpose: make Phase 06 usable by an internal operator by adding safe structured logs and turning the Compose, readiness, storage, and logging work into a reproducible Mac-to-GPU-host runbook and safety checklist.
Output: JSON logging setup, deployment docs, safety audit docs, and tests proving required logging/setup/safety sections stay present.
Scope note: this plan does not add login, cloud-provider-specific infrastructure, production object storage, metrics dashboards, or default deep model warmup.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator docs -> deployment actions | Runbook commands shape how the beta is started and debugged on a rented GPU host. |
| Safety docs -> beta use | The safety audit must prevent deployment from implying unauthorized voice or character impersonation. |
| Logs/docs -> user content | Troubleshooting instructions must avoid collecting raw voice content, prompts, transcripts, or audio payloads. |
| API logs -> operator/debug stream | Logs support debugging but must not leak voice content, prompts, transcript text, or audio bytes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-03-01 | Spoofing / Abuse | `docs/deployment/internal-beta-safety-audit.md` | high | mitigate | Explicitly prohibit protected-character and real-performer imitation claims in beta setup and sign-off. |
| T-06-03-02 | Information disclosure | `docs/deployment/internal-beta.md` | high | mitigate | Log inspection instructions use IDs/stage metadata and tell operators not to collect raw audio, prompt, or transcript payloads. |
| T-06-03-03 | Denial of service | GPU-host setup | medium | mitigate | Separate fixture validation from GPU runtime validation and make model warmup optional troubleshooting, not a readiness blocker. |
| T-06-03-04 | Tampering | beta checklist | medium | mitigate | Doc tests enforce required env vars, commands, health checks, and safety strings so the runbook cannot silently drop them. |
| T-06-03-05 | Information disclosure | `services/api/app/services/logging_config.py` | high | mitigate | Redact/omit raw text, transcript, prompt, and audio payload fields; test with sentinel strings. |
</threat_model>
