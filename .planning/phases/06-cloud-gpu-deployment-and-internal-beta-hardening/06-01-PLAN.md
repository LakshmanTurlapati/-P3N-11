<objective>
Create the deployable service-separation contract for Phase 06.

Purpose: make the no-login studio runnable as separate `web`, `api`, and `speech-worker` services under Docker Compose while preserving local deterministic tests and the browser's same-origin API routes.
Output: Compose file, env documentation, and runtime config tests proving the API can be configured for local fixture mode or an external worker service.
Scope note: this plan does not implement deep readiness, structured logging, or the runbook; those are covered by 06-02 and 06-03.
</objective>

## Artifacts this phase produces

- `compose.yaml`: Docker Compose handoff with services `web`, `api`, `speech-worker`, shared mounted storage, service health dependencies, and Compose-friendly commands.
- `.env.example`: documented values for `API_BASE_URL`, `THEATRICAL_VOICE_STUDIO_STORAGE_ROOT`, `THEATRICAL_VOICE_STUDIO_WORKER_ROOT`, `THEATRICAL_VOICE_STUDIO_WORKER_URL`, `THEATRICAL_VOICE_STUDIO_WORKER_MODE`, and fixture/runtime toggles.
- `services/api/app/services/worker_config.py`: shared worker runtime config helper with `WorkerRuntimeConfig` and `load_worker_runtime_config()`.
- `services/api/tests/test_deployment_config.py`: static/config tests for Compose service names, startup commands, env names, shared storage mount, and same-origin rewrite expectations.
- `services/api/tests/test_worker_config.py`: worker mode/env parsing tests shared by generation, audio turn, and conversation runtimes.
- `THEATRICAL_VOICE_STUDIO_WORKER_MODE`: runtime selector with at least `in_process` and `external` values.
- `THEATRICAL_VOICE_STUDIO_WORKER_URL`: API-to-worker HTTP base URL for the separate speech-worker service.
- `speech-worker` Compose service name: stable DNS name for the API worker boundary.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Next.js rewrite -> API | The browser must keep same-origin route paths and must not learn raw backend hosts. |
| API -> speech-worker | The API may call an external worker in Compose, but local tests keep fixture/in-process fallback. |
| Containers -> mounted storage | API and worker share audio/job storage through a volume instead of process-local temp files. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01-01 | Spoofing | `apps/web/next.config.ts` | medium | mitigate | Preserve server-side `API_BASE_URL` rewrites so browser code does not hard-code API hosts. |
| T-06-01-02 | Denial of service | `compose.yaml` | medium | mitigate | Add healthcheck entries and avoid model warmup in Compose startup checks. |
| T-06-01-03 | Tampering | worker mode env | medium | mitigate | Validate `THEATRICAL_VOICE_STUDIO_WORKER_MODE` and fail with explicit env-var messages. |
| T-06-01-04 | Information disclosure | service env | medium | mitigate | Do not add secrets or raw audio paths to browser-visible env; keep storage paths server-side. |
</threat_model>
